# FACKTS Music — password recovery and admin assistance

## New recovery flow

1. Control Room → People & access → open the user → Password assistance → Send password-reset link, or the user opens /forgot-password.
2. The email is generated by Supabase Auth using the account's registered authentication email, not an editable profile address.
3. The link redirects to the canonical FACKTS Music domain at https://music.facktsafrica.co.ke/auth/recovery.
4. The client-side landing page validates Supabase's implicit recovery tokens (or a verified token hash / supported PKCE code), removes credentials from browser history, establishes the verified recovery session, and opens /set-password?recovery=1.
5. The user enters and confirms a new password; Supabase updates the password and the session signs out, returning to /login for a fresh sign-in.

No password is generated, viewed, emailed or set by an administrator. Requests are audited by requesting administrator ID and target user ID, not with passwords or reset tokens. The admin request is throttled per target (ten minutes). The existing public Supabase email rate limit applies.

## REQUIRED Supabase Auth URL Configuration

This connected repository integration cannot inspect or edit the remote Auth URL Configuration directly. In the Supabase dashboard for Fackts Music (project ref ijczdvlbeikfozgkezgb), under Authentication → URL Configuration:

- Set **Site URL** to https://music.facktsafrica.co.ke
- Add exact allowed **Redirect URL** https://music.facktsafrica.co.ke/auth/recovery
- Preserve legitimate existing redirect URLs required for signup and invite flows.
- Remove localhost URL entries from production configuration only once development needs are accounted for. They are not needed for production reset emails.

Check Authentication → Email Templates → Reset password: use the standard {{ .ConfirmationURL }} link, or a correctly implemented custom token-hash verification link. Do not use a hard-coded localhost href or {{ .SiteURL }} when the configured site URL is not production. Check your custom SMTP/email provider and Auth rate-limit settings.

If the above settings are not changed, Supabase can send the email to localhost **even though the application code uses the production redirect**. A Vercel READY deployment is not proof that email delivery and password changing work.

## Validation

Automated checks cover canonical URL, admin permission, real auth user lookup, throttling, recovery callback support and the signed-in password-update call.

Before declaring end-to-end acceptance, perform a safe password-reset test with a consented test account (not a genuine user's account) and an actual inbox:

- Trigger a self-service reset and an admin-sent reset.
- Read the received URL; no localhost hostname should occur at any point.
- Open on a second browser/device.
- Complete verification, choose new password, land on login, sign in with new password.
- Confirm old password fails, session history behaves as expected and no tokens appear in diagnostics.
- Try an expired/reused link, confirm helpful guidance and the ability to resend.
- Verify error behaviour for SMTP failure and rate limiting.
- Confirm no existing music, project, session or financial data changes.

This change does not apply a database migration, rotate passwords or send recovery emails to specific users.
